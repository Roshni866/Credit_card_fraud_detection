# Credit Card Fraud Detection

This project compares four classifiers for credit-card fraud detection and measures the effect of applying SMOTE to the training data:

- Logistic Regression
- Random Forest
- XGBoost
- Linear Support Vector Machine (SVM)

Each model is evaluated twice: once on the original imbalanced training split and once on a SMOTE-resampled training split. Both versions are evaluated on the same held-out test split.

## Dataset

The project uses the Kaggle credit-card fraud dataset, with 284,807 transactions, 30 input features, and a `Class` target (`0` = legitimate, `1` = fraud). The dataset has 492 fraudulent rows, a fraud rate of approximately **0.173%**.

The CSV is not included in Git because it is approximately 151 MB. Put the downloaded file here:

```text
data/creditcard.csv
```

## Current measured results

The following values are from the latest run recorded in `smote_vs_baseline_results.csv`. The notebook uses a 70/30 train/test split with `random_state=42`; SMOTE is fitted only on the training data. Metrics are measured on the held-out test set.

| Model | Training data | Fraud recall | Precision | Specificity | Test AUC-ROC |
|---|---|---:|---:|---:|---:|
| Logistic Regression | No SMOTE | 62.50% | 86.73% | 99.98% | 0.9802 |
| Logistic Regression | SMOTE | 93.38% | 5.28% | 97.33% | 0.9812 |
| Random Forest | No SMOTE | 80.15% | 94.78% | 99.99% | 0.9621 |
| Random Forest | SMOTE | **86.76%** | 84.89% | 99.98% | 0.9851 |
| XGBoost | No SMOTE | 81.62% | 93.28% | 99.99% | 0.9860 |
| XGBoost | SMOTE | **86.76%** | 69.82% | 99.94% | **0.9893** |
| Linear SVM | No SMOTE | 59.56% | 87.10% | 99.99% | 0.9776 |
| Linear SVM | SMOTE | 92.65% | 6.80% | 97.98% | 0.9835 |

In this run, **Random Forest and XGBoost with SMOTE each achieved 86.76% fraud recall**. XGBoost with SMOTE had the highest test AUC-ROC. Higher recall can come with more false alarms; for example, Logistic Regression with SMOTE reached 93.38% recall but had 5.28% precision.

The image's stated **34% improvement** is not supported as a general result by this run. Relative recall changes from applying SMOTE were:

| Model | Recall without SMOTE | Recall with SMOTE | Relative recall change |
|---|---:|---:|---:|
| Logistic Regression | 62.50% | 93.38% | +49.4% |
| Random Forest | 80.15% | 86.76% | +8.3% |
| XGBoost | 81.62% | 86.76% | +6.3% |
| Linear SVM | 59.56% | 92.65% | +55.6% |

Therefore, the accurate summary is that SMOTE improved recall in this experiment, with the size of the improvement depending on the model. Do not present 34% as a measured result for this run.

## Project structure

```text
.
├── app.py                              # Streamlit prediction and performance UI
├── credit_card_fraud_detection.ipynb   # Main training and evaluation workflow
├── data/
│   └── creditcard.csv                  # Download separately; excluded from Git
├── model/                              # Fitted models and scaler; generated by notebook
├── plots/                              # Evaluation plots generated by notebook
├── requirements.txt
└── smote_vs_baseline_results.csv       # Latest per-model test metrics
```

The notebook uses a shared preprocessing/evaluation flow and a model registry, making it straightforward to add or replace a classifier without duplicating the rest of the comparison. The Streamlit app provides a model and training-data selector for the saved model files.

## Setup on Windows

Open PowerShell in the project directory:

```powershell
cd "C:\path\to\Credit_card_fraud_detection"
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Ensure the dataset is at `data\creditcard.csv`.

## Train and evaluate

1. Open `credit_card_fraud_detection.ipynb` in VS Code.
2. Select the Python kernel from `.venv`.
3. Choose **Run All** and wait for all cells to finish. Random Forest is generally the slowest model.
4. Check the printed metrics for every model/training-data combination and review the final comparison table.

The notebook writes:

- `smote_vs_baseline_results.csv` — test metrics and confusion-matrix counts for all eight runs.
- `model\` — eight trained model files and the shared scaler, used by the app.
- `plots\` — ROC curves, confusion matrices, model comparison, and class distribution.

SMOTE is applied to the training split only; the test split is kept unchanged for evaluation.

## Run the Streamlit app

After running all notebook cells, from the project directory run:

```powershell
.\.venv\Scripts\Activate.ps1
streamlit run .\app.py
```

Open the local URL printed in the terminal. On the **Make Prediction** page, choose a model and whether it was trained with SMOTE. The app's sample-input tab generates demonstration features; use the detailed-input tab to enter values yourself.

Linear SVM provides a decision score rather than a calibrated fraud probability.

## Evaluation notes

This is a model-comparison demonstration, not a production fraud-decision service. The test split contains relatively few fraud examples, so recall changes in noticeable increments. The reported values are tied to the split, random seed, dataset, and package versions; rerun the notebook to regenerate them. Accuracy alone is not a sufficient metric for this imbalanced dataset.
